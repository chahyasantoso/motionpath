# MotionPath v4.2: rig graph normalization

> **Phase 5 of this plan was marked complete in error.** Batched publishing shipped as a helper that ordered and de-duplicated dirty nodes but could not publish a dirty node's dependents, so a marked parent left its children rendering stale patches. The unit tests passed only because they fed the publisher fake object-literal tracks. The correct contract, the fix, and its coverage live in `docs/V4.3-GRAPH-CORRECTNESS-PLAN.md`. Phases 1-4 and 6 stand as written.

## Goal

Make multi-track mechanics, especially FK rigs like Walker, compile their observation graph once and reuse the result for every frame.

## Why now

Walker proves the current engine handles declarative FK correctly: 14 tracks, parentWorld inputs, cycle-safe composition, and direct DOM subscriptions. The weak point is repeated recursive discovery at compose time and repeated authored observation wiring across scenes.

## Proposed phases

1. **Graph IR**: normalize `tracks[].observes` into immutable nodes and edges with input/output mapping metadata. **Complete.**
2. **Validation**: reject missing nodes, duplicate edges, self-cycles, cycles, invalid roles/targets, and ambiguous output ownership before GSAP mounting. **Complete for graph diagnostics.**
3. **Topological order**: compute stable parent-before-child order and expose diagnostics for tools and AI. **Complete.**
4. **Compiled composition**: let a Motion/TrackGroup compose in cached order, preserving cycle-safe behavior as a development assertion. **Complete.**
5. **Batched publishing**: collect dirty track patches once per engine tick, then publish subscribers in graph order. **Superseded by v4.3.** Ordering and de-duplication shipped; dependent publishing, invalidation propagation, the cross-flush cache, and failure isolation did not. Delivered in v4.3 phases 4-5.
6. **Benchmarks**: compare Walker, 50-track, and 250-track rigs for compile time, compose time, and DOM writes. **Complete as repeatable npm benchmark command.**

## Non-goals

- No generic orchestration language.
- No second animation clock or requestAnimationFrame loop.
- No React state in the runtime path.
- No renderer-specific graph logic.

## Acceptance criteria

- Existing projects validate and compose unchanged.
- Walker has no per-frame graph traversal.
- Cycle diagnostics remain actionable and deterministic.
- Headless composition tests run without React or DOM.
- Benchmarks show no regression for non-graph tracks.

## First implementation slice

Add `normalizeObservationGraph(motion)` and `topologicalTrackOrder(graph)` under `packages/core/src/usecases/`, return frozen JSON-safe IR, and make validator diagnostics consume the same IR. Add Walker and diamond/cycle fixtures before changing runtime composition.

### Slice status

Phases 1-4 and 6 are delivered as described: the graph IR is immutable and deterministic, diagnostics are available before runtime mounting, mounted motions carry compiled graph order, and `npm run benchmark:rig` covers 14, 50, and 250-track chains. Phase 5 was overstated and is corrected in v4.3, which added dependent publishing, a persistent patch cache, GraphBinding, and real-Track test fixtures.

### Lesson worth keeping

A test suite that constructs its own convenient doubles can certify a component that cannot work against the real one. The publisher's original tests passed object literals with a `compose(raw, composed)` signature no `Track` implements. Graph tests now use real `Track` fixtures, and that rule is enforced in `docs/API-REFERENCE.md`.
