# MotionPath v4.3: graph publishing correctness

> Status: **proposed**. Supersedes the "Complete" claims in phases 4-6 of `docs/V4.2-RIG-GRAPH-PLAN.md`.

## Why this document exists

v4.2 shipped `normalizeObservationGraph`, `GraphPublisher`, `TrackGroup.composeGraph`, and a rig benchmark, and marked all six phases complete. A line-by-line review of `GraphPublisher.js`, `Track.js`, `Motion.js`, and `normalizeObservationGraph.js` shows the batched-publishing layer is **not correct against real `Track` instances**. It passes its unit tests only because those tests substitute object literals for tracks, and those literals happen to implement a different `ctx` contract than the real `Track.compose` does.

The headline problem is not performance. It is that `GraphPublisher` can publish the wrong set of nodes, and its memo cache is dead code when wired to production `Track` objects.

This plan fixes every defect found, end to end, with tests that exercise real tracks. Partial adoption is explicitly not acceptable: D1 and D2 must land together or the publisher stays broken.

---

## 1. Defect register

| ID | Defect | Where | Severity |
|----|--------|-------|----------|
| D1 | Publisher has no edge data, so it publishes only the marked node and never its dependents | `GraphPublisher` | Critical |
| D2 | `ctx` key contract mismatch: publisher/TrackGroup key by string id, `Track.compose` keys by instance | `GraphPublisher`, `Motion.js`, `Track.js` | Critical |
| D3 | Dirty set is cleared before compose/publish succeed; a mid-loop throw permanently loses pending nodes | `GraphPublisher.flush` | High |
| D4 | No cross-tick memo; `#dirty` gates publish only, never compute | `GraphPublisher.flush` | High |
| D5 | `#order` frozen at construction (same for `Motion`/`TrackGroup` `#graphOrder`), while `#tracks` is a live reference | `GraphPublisher`, `Motion.js` | High |
| D6 | Runtime cycles unvalidated in `setObserved`, and `COMPOSING` fallback silently drops observed input | `Track.js` | High |
| D7 | `destroy()` and `removeChild()` leave dangling observers pointing at dead tracks | `Track.js` | High |
| D8 | `compose()` / `getSnapshot()` have no destroyed guard; publisher never drops destroyed tracks | `Track.js`, `GraphPublisher` | Medium |
| D9 | `#observed` keyed by Track instance collapses distinct IR edges (role/input) to one, last-write-wins | `Track.js` | Medium |
| D10 | `markDirty()` silently no-ops on unknown ids | `GraphPublisher` | Medium |
| D11 | Normalizer returns a partial `order` alongside cycle errors; callers ignoring `errors` get silent non-composition | `normalizeObservationGraph` | Medium |
| D12 | Edge dedup key built by delimiter-less concatenation, can collide across distinct id pairs | `normalizeObservationGraph` | Low |

### Evidence

**D1.** The constructor accepts `{ order, tracks, publish }`. No edges. `markDirty(A)` adds only `A` to `#dirty`, and `flush()` publishes exactly `dirty.has(id)`. If `B` observes `A`, `B`'s composed patch changed but `B` is never published. The only currently-correct usage is `markAllDirty()` every frame, which is what `performance/rig-graph-benchmark.mjs` does, which is why the benchmark never exposed this.

**D2.** `GraphPublisher.flush` does `composed.set(id, patch)` (string key). `Track.compose` does `const cached = ctx.get(this)` and `ctx.set(this, patch)` (instance key). So against real tracks the publisher's writes are never read and the tracks' writes are never seen by the publisher's `composed.get(id)` contract. `TrackGroup.composeGraph()` in `Motion.js` repeats the identical mistake with its `patches` map. Both memoization paths are inert; every observed source is recomputed once per dependent, which is quadratic on a diamond.

**D3.** `flush()` swaps `this.#dirty = new Set()` at the top, then composes and publishes in a loop with no try/finally. One throwing plugin discards every other pending node for good.

**D4.** `const composed = new Map()` is constructed per call. A node untouched for 500 ticks is fully recomposed on tick 501.

**D5.** `this.#order = [...order]` with no setter or rebuild path, but `this.#tracks = tracks` keeps a live reference. Tracks added to that map after construction exist but never compose.

**D6.** `setObserved(track, mapFn, opts)` performs zero validation, not even the self-observation check the normalizer enforces statically. When re-entrancy is detected, `compose` returns `composePatch(..., rawData ?? this.getSnapshot(), ...)`, silently dropping the observed contribution instead of throwing. This violates the locked principle "prefer throws over silent failures; validator rules must throw, never silently strip."

**D7.** `destroy()` clears `this.#observed` (its own outbound edges) and nothing else. There is no reverse index, so notifying dependents is not merely skipped, it is impossible. `removeChild()` never touches observation state at all.

**D8.** `progress()`, `_mount()`, and `addChild()` guard on `#destroyed`. `compose()` and `getSnapshot()` do not, and `destroy()` kills the interpolation timeline, so a destroyed-but-still-registered track composes from a dead timeline indefinitely.

**D9.** The IR's dedup key is `source + target + role + input`, so `A -> B` as `output` and `A -> B` as `input:"x"` are two legal distinct edges. `#observed.set(track, {...})` can hold only one entry per source instance. The second `setObserved` silently overwrites the first. Runtime cannot represent its own schema.

**D11.** On cycle detection the normalizer pushes an error but still returns the partial Kahn order it managed to build, and `topologicalTrackOrder` hands it over without checking `errors`.

**D12.** `` `${edge.source}${targetNode}${role}${edge.target ?? ""}` `` collides for `{source:"A", target:"BC"}` vs `{source:"AB", target:"C"}`.

## 2. Root causes

Three, not twelve:

1. **The publisher was given nodes but not edges.** Dirty propagation, dependency-scoped invalidation, and correct publish sets are all downstream of this single omission.
2. **The compose context has two incompatible key conventions** and no shared type enforcing either. Tests using fakes made both conventions look correct simultaneously.
3. **Observation is a one-way, unvalidated, unversioned edge.** No reverse index, no cycle check, no lifecycle signal, no revision counter. Every dynamic-topology feature (pop/rewire, click-to-spawn, infection spread) needs all four.

## 3. Target design

### 3.1 `ComposeContext` (fixes D2)

New file: `packages/core/src/usecases/ComposeContext.js`. One type, dual-indexed, so both key conventions resolve to the same slot.

```js
export class ComposeContext {
  #byTrack = new Map();
  #byId = new Map();
  #inFlight = new Set();

  get(key) {
    return typeof key === "string" ? this.#byId.get(key) : this.#byTrack.get(key);
  }
  has(key) { return this.get(key) !== undefined; }
  set(track, patch) {
    this.#byTrack.set(track, patch);
    const id = typeof track === "string" ? track : track?.id;
    if (id !== undefined) this.#byId.set(id, patch);
    return patch;
  }
  enter(track) { /* throws CycleError if already in #inFlight */ }
  exit(track) { this.#inFlight.delete(track); }
}

export function toComposeContext(ctx) {
  if (ctx instanceof ComposeContext) return ctx;
  const next = new ComposeContext();
  if (ctx instanceof Map) for (const [k, v] of ctx) next.set(k, v);
  return next;
}
```

`Track.compose` starts with `ctx = toComposeContext(ctx)` so existing callers passing a raw `Map` keep working during migration. `GraphPublisher` and `TrackGroup.composeGraph` both switch to `ComposeContext`. The `COMPOSING` sentinel is replaced by `#inFlight` + `enter`/`exit`, which is what makes D6 throwable.

### 3.2 Publisher owns the graph (fixes D1, D4, D5, D10)

`GraphPublisher` takes the normalized graph, not a bare order:

```js
new GraphPublisher({ graph, tracks, publish, strict = true, verifyIncremental = false })
```

Internal state:
- `#order` — topological order, replaceable via `applyGraph(graph)`.
- `#dependents: Map<id, Set<id>>` — reverse index built from `graph.edges`.
- `#cache: Map<id, patch>` — **persisted across flushes**.
- `#invalid: Set<id>` — needs recompute.
- `#dirty: Set<id>` — needs publish.

`markDirty(id)`:
1. Throw in strict mode if `id` is unknown (D10).
2. Compute the transitive downstream closure of `id` via `#dependents` (BFS, visited set, so cycles cannot hang it).
3. Add the whole closure to both `#invalid` and `#dirty`. Ancestors are untouched.

`flush()`:
1. Recompose only ids in `#invalid`, in `#order`, seeding a fresh `ComposeContext` from `#cache` for the valid ones so untouched ancestors are read, not recomputed.
2. Write results back into `#cache`.
3. Publish every id in `#dirty` (which now includes dependents).
4. Clear `#invalid` and `#dirty` only for ids that completed (D3).

Topology mutation API: `applyGraph(graph)`, `addTrack(id, track, { observes })`, `removeTrack(id)`, `addEdge(edge)`, `removeEdge(edge)`. Each rebuilds `#dependents`, patches `#order` (incremental topological repair, full re-sort as the fallback), and invalidates the affected closure. `Motion` and `TrackGroup` get the same treatment: `#graphOrder` becomes settable via `applyGraphOrder(order)` instead of construction-only.

### 3.3 Invalidation is pushed, not assumed (the D4 correctness half)

A persistent cache is only safe if every state mutation invalidates. Otherwise we trade wasted work for stale frames, which is worse.

- `Track` gains a private `#revision`, bumped by `progress()`, `setObserved()`, `removeObserved()`, `addChild()`, `removeChild()`, and `destroy()`.
- On bump, `Track` emits `track:invalidated { id }` on its `eventBus`.
- `GraphPublisher` subscribes on construction and calls `markDirty(id)`. GSAP drives animation through the `progress` proxy setter, so per-frame invalidation is covered by the `progress()` hook.
- Dev-only `verifyIncremental: true` recomputes the **entire** graph after each flush and deep-compares against `#cache`, throwing on divergence. This is the guard that keeps the cache honest; it runs in the test suite on every graph test, and off in production.

### 3.4 Observation edges become first-class (fixes D6, D7, D9)

`Track.#observed` is re-keyed from `Track` instance to composite edge key:

```js
const edgeKey = (sourceId, role, input) => [sourceId, role, input ?? ""].join("");
// value: { source: Track, mapFn, role, input }
```

This matches the IR's dedup key exactly, so `A -> B` input and output edges coexist as the schema already permits.

`Track.#observers: Set<Track>` is the reverse index, maintained by `setObserved`/`removeObserved`.

- `setObserved(track, mapFn, opts)` throws on self-observation and on any edge that would create a cycle (walk upstream from `track` via `#observed`; if `this` is reachable, throw `CycleError` **before** mutating, so the operation is atomic). Registers `this` in `track.#observers`.
- `removeObserved(track, opts)` removes matching edges and deregisters from `track.#observers`.
- `replaceObserved(oldSource, newSource, mapFn, opts)` — one atomic call for the pop-and-rewire primitive. Validates the new edge first, swaps only if valid. This is the API the Zuma-style design should call; doing it as remove-then-add leaves a window where the graph is disconnected.
- `destroy()` iterates `#observers` and calls `observer.removeObserved(this)`, then emits `track:source-destroyed { id, observerIds }` so rewire logic can respond. Dangling references become impossible rather than merely discouraged.
- `removeChild(id)` detaches the child's observation edges in both directions before unmounting.
- `compose()` and `getSnapshot()` throw if `#destroyed` (D8). `GraphPublisher` listens for destruction and calls `removeTrack(id)`.

### 3.5 Normalizer hardening (fixes D11, D12)

- Dedup key gets a `` separator and is shared with `Track`'s `edgeKey` via a single exported helper, so the two can never drift again.
- The returned IR gains `valid: errors.length === 0`.
- `topologicalTrackOrder(graph, { strict = true })` throws an aggregated error when `graph.errors` is non-empty instead of returning a partial order.
- `GraphPublisher` and `Motion` reject an invalid graph at construction.
- The normalizer itself stays pure and diagnostic-only; throwing is the compile/mount boundary's job.

## 4. Phases

Each phase is independently mergeable and leaves the suite green.

**Phase 0 — failing tests first.** Write the real-`Track` integration tests from section 5 and land them red. No production changes. This is the gate that prevents another fake-test pass.

**Phase 1 — `ComposeContext` (D2).** New type, `Track.compose` migration, `GraphPublisher` and `TrackGroup.composeGraph` migrated. Diamond memoization verified by counting real plugin invocations.

**Phase 2 — edges, dependents, persistent cache (D1, D3, D4, D10).** Publisher takes the graph, builds the reverse index, propagates dirty downstream, persists the cache, makes `flush()` failure-safe, and adds `verifyIncremental`.

**Phase 3 — mutable topology (D5).** `applyGraph`/`addTrack`/`removeTrack`/`addEdge`/`removeEdge` on the publisher, `applyGraphOrder` on `Motion`/`TrackGroup`.

**Phase 4 — observation lifecycle and cycle safety (D6, D7, D8, D9).** Composite edge keys, reverse observer index, throwing cycle validation, `replaceObserved`, destroy/removeChild cleanup, destroyed guards.

**Phase 5 — normalizer hardening (D11, D12).** Shared key helper, `valid` flag, strict `topologicalTrackOrder`.

**Phase 6 — benchmarks and docs.** Idle-majority scenario, updated v4.2 plan status, `graphify update .`.

## 5. Test plan

**Non-negotiable: no test in `packages/core/src/usecases/__tests__/GraphPublisher.test.js` may use an object literal as a track.** The two existing tests there are deleted and rewritten against real `Track` instances built by a shared `makeTrack()` fixture. The fakes are the reason these defects shipped as "Complete".

Coverage:

1. **Diamond memoization** — `A`; `B` and `C` observe `A`; `D` observes `B` and `C`. One flush composes `A` exactly once. Asserted by spying on the plugin, not on `compose`.
2. **Dependent publishing (D1)** — `markDirty("A")` publishes `A`, `B`, `C`, `D` in topological order.
3. **Ancestors untouched** — `markDirty("D")` recomposes only `D`; `A`, `B`, `C` come from cache.
4. **Cross-tick cache (D4)** — flush, then flush again with no mutation: zero composes, zero publishes.
5. **Sparse graph** — 300-node chain, mark 1 dirty, assert composes equal the downstream closure size, not 300.
6. **Invalidation fuzz** — 1000 iterations of random graph + random mutations, comparing incremental output against a from-scratch full recompute. Any divergence fails. This is what proves the persistent cache is not lying.
7. **Error isolation (D3)** — a publish callback throws on node 3 of 6: remaining nodes stay pending, the error surfaces as an `AggregateError`, the next flush publishes the stragglers.
8. **Runtime cycle (D6)** — `setObserved` creating `A -> B -> A` throws `CycleError`, and the graph is byte-identical to its pre-call state (atomicity).
9. **No silent strip (D6)** — assert the old `COMPOSING` fallback path is gone: a forced re-entrant compose throws instead of returning a snapshot-only patch.
10. **Destroy cleanup (D7, D8)** — destroying an observed source deregisters it from every observer, the publisher drops it, the next flush neither composes nor throws, and calling `compose()` on the destroyed track throws.
11. **Pop and rewire** — chain of 10, pop index 5 via `replaceObserved`, assert node 6 observes node 4 and output is identical to a fresh 9-node chain.
12. **Multi-edge (D9)** — `A -> B` as `output` plus `A -> B` as `input:"x"` both survive `setObserved` and both contribute to the composed patch.
13. **Topology mutation (D5)** — `addTrack` after construction composes on the next flush; `removeTrack` stops it; order stays topologically valid.
14. **Normalizer (D11, D12)** — cycle IR reports `valid: false` and `topologicalTrackOrder` throws; ids `A`/`BC` vs `AB`/`C` produce two distinct edges, not one deduped edge.
15. **`TrackGroup.composeGraph` parity** — same diamond, same single-compose guarantee, since it shares the D2 bug today.

Benchmarks (`performance/rig-graph-benchmark.mjs`): add an **idle-majority** scenario, 300 nodes with 5 active per frame. Target is compose cost proportional to the dirty closure rather than node count, and no regression on the existing 14/50/250 chains where every node is dirty.

## 6. Breaking changes

- `GraphPublisher` constructor takes `graph` instead of `order`. `order` stays accepted for one minor version, warns, and produces a publisher with an empty dependent index (current behavior, explicitly degraded).
- `markDirty` throws on unknown ids by default. Opt out with `strict: false`.
- `Track.compose` on a destroyed track now throws.
- `setObserved` now throws on cycles and self-observation.
- `topologicalTrackOrder` throws on an invalid graph by default.

## 8. Out of scope

- Parallel or worker-based composition.
- A generic reactive/signals runtime. The dependent index is graph-specific on purpose.
- Renderer-specific batching. The publisher stays framework-agnostic.
- Changing the declarative `observes` schema. This plan makes the runtime match the schema that already exists.
