# MotionPath v4.3: correct graph publishing

> Status: **proposed, revision 4**. This is the v4.3 base plan. It supersedes the "Complete" claim on phase 5 of `docs/V4.2-RIG-GRAPH-PLAN.md`.
>
> Phase 0 red tests live on [`test/v4.3-graph-correctness-phase0`](https://github.com/chahyasantoso/motionpath/tree/test/v4.3-graph-correctness-phase0).

## Decision summary

The previous plan mixed two different responsibilities. That was the mistake.

- **`Track` remains a local composition primitive.** Its compose context is per root call, its standalone mutual-observation behavior remains supported, and it does not own graph lifecycle.
- **`GraphPublisher` owns the runtime DAG.** It owns graph edges, topological order, dirty propagation, cache invalidation, cycle validation for rewires, duplicate ids, and cleanup of destroyed nodes.
- **The publisher cache is persistent and explicit.** This is what makes dirty tracking real. It is separate from `Track`'s per-call memo and is invalidated by publisher-controlled state changes.
- **No reverse observer registry is added to `Track`.** The publisher already has the authoritative edge index, so duplicating it inside every track would create two lifecycle systems that can drift.

This preserves the useful old decisions while moving graph-specific guarantees to the only object that actually knows the whole graph.

## 2. What stays, what changes

### 2.1 Keep `Track` per-call composition

`Track.compose(rawData, ctx)` keeps a fresh `Map` for each external root call and threads it through recursive observation. The map contains the `COMPOSING` sentinel and completed patches for that call only. This prevents diamond recomputation without making a stale cross-frame cache part of `Track`.

This is necessary for scrubbing and seeking: two root calls must observe current proxy state and recompute. Do not put an epoch/frame cache on `Track`.

Standalone tracks remain permissive: mutual observation continues to use the existing cycle back-edge fallback. That behavior is useful for the low-level primitive and is already covered by `Track.test.js`. It is not the contract of a publisher-managed graph.

### 2.2 Publisher owns the graph contract

Use:

```js
new GraphPublisher({ graph, tracks, publish, strict = true })
```

The publisher stores: 

- `#order`: current topological order.
- `#upstream`: source ids for every node, including role/input metadata.
- `#tracks`: id to real `Track`.
- `#marked`: directly invalidated ids.
- `#cache`: last successfully composed patch per id.
- `#known`: registered ids, used for duplicate/unknown checks.

`markDirty(id)` is O(1): validate, then add to `#marked`. It does not walk descendants.

`flush()` makes one forward pass over topological order. A node recomposes when directly marked, missing from cache, or any upstream node recomposed successfully. Otherwise it reads its cached patch. The same pass determines the publish set, so a source and every affected dependent are published exactly once in order.

This is O(V+E) per flush for the dependency check, with composition proportional to the invalidated closure. No per-mark BFS and no full-graph compose when most nodes are idle.

### 2.3 Persistent cache correctness

The cache is not allowed to become an optimistic shortcut.

- A successful `progress`, observation replacement, edge mutation, topology mutation, or explicit `markDirty` invalidates the relevant node and all downstream nodes through the forward pass.
- Cache misses always compose, even if the node was not explicitly marked.
- If a node fails during compose or publish, its cache entry is not replaced. The node remains pending. Its downstream nodes are blocked for that flush and remain pending for retry, rather than consuming stale upstream output.
- `flush()` collects failures, finishes independent nodes, then throws an `AggregateError`. The next flush retries failed and blocked nodes.
- A development-only `verifyIncremental` mode recomposes the complete graph from scratch after a successful flush and deep-compares published/cache results. It is a correctness oracle, not a production hot path.

The cache belongs to `GraphPublisher`, not `Track`, so `Track` keeps the locked per-call semantics.

### 2.4 Graph-owned lifecycle, not a Track reverse registry

The earlier proposal added `Track.#observers`. That is unnecessary duplication and would make `Track` know about graph ownership. Instead, the publisher's `#upstream` and reverse dependent index are authoritative.

All graph changes go through publisher APIs:

```js
applyGraph(graph, tracks)
addTrack(track, { observes })
removeTrack(id)
addEdge(edge)
removeEdge(edge)
replaceEdge(oldEdge, newEdge)
```

`replaceEdge` validates the complete candidate graph first, then commits the edge and order atomically. This is the pop-and-rewire primitive. There is no remove-then-add window.

If a track has been destroyed directly, the publisher detects it before composition, removes the node and all incident edges, rebuilds the order, invalidates affected dependents, and never calls `compose()` on the dead object. `Track.compose()` and `getSnapshot()` still throw on destroyed tracks, so accidental direct use fails loudly.

This gives dynamic graphs automatic cleanup without a reverse registry, event allocation on every frame, or caller-dependent observer cleanup.

### 2.5 Runtime edge representation

`Track.#observed` changes from `Map<Track, record>` to insertion-ordered edge records keyed by a shared composite key:

```js
edgeKey(sourceId, role, input)
// [sourceId, role, input ?? ""].join("")
// value: { source, role, input, mapFn }
```

This allows the same source to contribute both an input and output edge, matching the normalized IR. `observedSources` remains deduplicated for compatibility; `observedEdges` exposes the full edge set.

`Track.setObserved()` remains standalone-safe and validates only malformed/self edges. GraphPublisher validates cycles against its candidate graph before calling it. The publisher, not `Track`, decides whether a runtime edge is legal in the managed DAG.

### 2.6 One compose key

Use track ids as the canonical key in the per-call context. `Track`, `GraphPublisher`, and `TrackGroup.composeGraph()` must all read and write the same key space. Remove the publisher's redundant `composed.set(id, patch)` write. `TrackGroup.composeGraph()` returns exactly one patch per id.

D13 is implemented before this migration: registration and mounting reject duplicate ids.

## 3. Normalizer and topology

- Share the delimiter-safe edge key helper between normalizer and runtime edge records.
- Return `valid: errors.length === 0` from `normalizeObservationGraph`.
- `topologicalTrackOrder(graph, { strict: true })` throws an aggregated diagnostic for invalid graphs instead of handing callers a partial order by default.
- GraphPublisher rejects invalid graphs at construction and during `applyGraph`/edge mutation.
- Topology changes re-run a stable O(V+E) topological sort. Rewires are user-event rate; incremental topo repair is needless complexity.
- A failed graph mutation leaves the old graph fully intact.

## 4. Implementation phases

**Phase 0, complete on the test branch:** red tests using real `Track` fixtures. Keep the original standalone cycle and per-call compose tests as locked regression tests.

**Phase 1, identity and context:** duplicate-id checks, shared id-keyed compose context, real TrackGroup parity, destroyed guards.

**Phase 2, publisher core:** graph input, upstream/dependent indexes, O(1) marking, one forward flush pass, dependent publishing, AggregateError retry semantics.

**Phase 3, persistent invalidation:** publisher cache, cache-miss behavior, mutation invalidation, blocked downstream failures, `verifyIncremental`. Add the idle-majority benchmark before declaring the optimization complete.

**Phase 4, topology and lifecycle:** atomic add/remove/replace edge APIs, graph-owned cleanup of destroyed tracks, stable re-sort, late registration, pop-and-rewire.

**Phase 5, observation parity:** composite runtime edges, `observedEdges`, shared edge key, input/output coexistence, publisher-to-Track wiring.

**Phase 6, normalizer and migration:** strict invalid graph boundary, delimiter collision fix, update v4.2 status/docs, run `graphify update .`, and remove the fake GraphPublisher tests.

## 5. Non-negotiable tests

No graph test uses an object literal as a track. All graph tests use real Track instances and assert plugin invocations or published patches.

1. Marking a root publishes the full downstream closure in topological order.
2. Marking a sink does not publish ancestors.
3. A 300-node chain with five active nodes composes only invalidated closure nodes.
4. Repeated marks coalesce.
5. Independent branches still publish when another branch throws.
6. Failed nodes and blocked dependents retry on the next flush.
7. Duplicate ids, unknown ids, invalid graphs, and cycle rewires throw without mutation.
8. Late add/remove/replace operations rebuild a valid order atomically.
9. Destroyed tracks are removed before compose and leave no dangling graph edge.
10. Input and output edges from one source coexist; `observedSources` remains backward-compatible.
11. Shared diamond ancestor composes once per flush, while two standalone root calls recompute.
12. `TrackGroup.composeGraph()` returns one id-keyed patch per track.
13. A seeded DAG fuzz suite compares incremental output and publish order with a from-scratch oracle.
14. Normalizer collision, duplicate edge, and strict cycle diagnostics are deterministic.

## 6. Breaking changes

- GraphPublisher's preferred constructor takes `graph`; legacy `order` mode is temporary and explicitly edge-less.
- Unknown ids throw by default; `strict: false` preserves a compatibility no-op.
- Duplicate graph ids throw.
- Graph-managed edge mutations must use publisher APIs; direct `Track.setObserved()` cannot update publisher topology.
- `Track.compose()` and `getSnapshot()` throw after destruction.
- Strict topological order throws on invalid graphs.

## 7. Definition of done

- All 13 defects have regression coverage.
- No graph test uses fake tracks.
- Standalone mutual observation and per-call compose scoping remain green unchanged.
- Incremental output matches full recomposition under seeded fuzz and `verifyIncremental`.
- Idle-majority benchmark demonstrates a win before persistent caching is called complete.
- Pop-and-rewire is atomic and cleanup is publisher-owned.
- v4.2 documentation is downgraded with a pointer to this plan.

## 8. Out of scope

Parallel composition, worker threads, a generic signals runtime, renderer-specific batching, and changing the declarative `observes` schema.
