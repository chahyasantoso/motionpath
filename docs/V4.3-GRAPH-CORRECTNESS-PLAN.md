## 0. Revision log

Kept rather than quietly edited, because the corrections are the most useful part of this document.

### Revision 2 — corrections to rev 1

Reviewed against `progress/v4/compose-per-call-scoping-brief.md`, `progress/v4/observe-multisource-brief.md`, and the existing `Track.test.js`.

**Correctness errors in rev 1:**

- **R1-E1: D2's impact was overstated.** Rev 1 claimed the publisher's memo is inert against real tracks and that diamonds recompute quadratically. False. `flush()` threads *the same* `composed` Map through every `track.compose(undefined, composed)` call, and `Track` writes instance-keyed entries into it, so they accumulate across the loop and the memo genuinely works. What is actually broken is narrower: the publisher's own `composed.set(id, patch)` string-keyed writes are never read by any real track (dead work, double-populating the map), and the "parent context" contract its unit test asserts is one no real `Track` can consume. D2 drops from Critical to Medium. The observable defect is `TrackGroup.composeGraph()`, which *returns* that dual-keyed map to callers.
- **R1-E2: D6 and D7 contradict locked decisions.** Rev 1 proposed making `compose()` throw on cycles and `destroy()` clean up observers. Both are specified the other way. `compose-per-call-scoping-brief.md` locks the silent back-edge fallback ("Do not return `{}` or a raw snapshot") and `Track.test.js` asserts `expect(() => a.compose()).not.toThrow()` with an exact expected fallback value. `observe-multisource-brief.md` states "No lifecycle coupling, no ownership... Track holds no reverse registry" as a deliberate choice. Still worth changing, but as *argued policy reversals with migration*, not bug fixes.

**Efficiency errors in rev 1:**

- **R1-P1: eager transitive closure in `markDirty` is O(n^2) per frame.** GSAP drives `progress()` on every animating track each tick, so `markDirty` fires once per active node, and rev 1 had each call BFS its own downstream closure. On a 300-node chain with everything animating that is ~45,000 steps per frame spent deciding what is dirty, costing more than the recompute it was meant to avoid. Replaced with a single forward pass (§3.2).
- **R1-P2: `ComposeContext` dual-indexing** added two map writes and two lookups per node per flush to keep both key conventions alive forever. Pick one canonical key (§3.1).
- **R1-P3: a separate `#inFlight` Set** duplicates what the existing `COMPOSING` sentinel already does in one lookup.
- **R1-P4: eventBus emission per `progress()`** allocates a payload object per track per frame (300 tracks at 60fps is ~18k short-lived objects/sec) for something a plain injected callback delivers free.
- **R1-P5: incremental topological repair** was premature. Topological sort is O(V+E) and rewires happen at user-event rate, not frame rate. Just re-sort.

### Revision 3 — correction to rev 2, found while writing the phase 0 tests

- **R2-E1: rev 2 still had cycle rejection too broad.** It said `setObserved` throws on "any edge that would close a cycle." Writing the test exposed that this breaks `Track.test.js`'s "is cycle-safe: mutual observation resolves synchronously" case, which covers mutual observation as a *supported feature*, not an accident. The DAG requirement does not come from `Track`; it comes from `GraphPublisher` needing a topological order. So validation belongs at graph membership, not on every `Track`. Corrected in §3.4. This is the third time reconciling against the locked briefs changed the answer, which is the argument for writing the tests before the implementation.

## 1. Why this document exists

v4.2 shipped the graph IR, `GraphPublisher`, `TrackGroup.composeGraph`, and a rig benchmark, and marked all six phases complete. The batched-publishing layer is not correct: it can publish the wrong *set* of nodes, and its only test coverage uses object literals in place of `Track` instances, which is why that went unnoticed.

The headline defect is **D1**, not performance. Everything else is severity-ordered behind it.

## 2. Defect register

| ID | Defect | Where | Severity |
|----|--------|-------|----------|
| D1 | Publisher holds no edges, so `markDirty(A)` never publishes A's dependents | `GraphPublisher` | Critical |
| D3 | Dirty set is cleared before compose/publish run; one throw permanently loses every other pending node | `GraphPublisher.flush` | High |
| D5 | `#order` frozen at construction while `#tracks` is a live reference, so late-added tracks never compose | `GraphPublisher`, `Motion.js` | High |
| D7 | Destroying an observed source leaves dependents holding a dead `Track`; no reverse registry exists | `Track.js` | High (by design, see §3.4) |
| D13 | No global track id uniqueness; `addChild` only enforces per-parent uniqueness, but the graph is id-keyed | `Track.js`, `GraphPublisher` | High |
| D2 | Publisher/TrackGroup write string keys into a ctx that `Track` reads by instance: dead writes, and `composeGraph()` returns a dual-keyed map | `GraphPublisher`, `Motion.js` | Medium |
| D6 | `setObserved` performs zero validation, so a runtime rewire can break the publisher's topological order | `Track.js` | Medium |
| D8 | `compose()` / `getSnapshot()` have no destroyed guard, and the publisher never drops destroyed tracks | `Track.js`, `GraphPublisher` | Medium |
| D9 | `#observed` keyed by Track instance cannot represent two distinct IR edges between the same pair | `Track.js` | Medium |
| D10 | `markDirty()` silently no-ops on an unknown id | `GraphPublisher` | Medium |
| D11 | Normalizer returns a partial `order` alongside cycle errors; callers ignoring `errors` silently skip nodes | `normalizeObservationGraph` | Medium |
| D4 | No cross-tick memo: `#dirty` gates publish, never compute | `GraphPublisher.flush` | Low (scenario-specific, see §3.3) |
| D12 | Edge dedup key concatenated without a delimiter, can collide across distinct id pairs | `normalizeObservationGraph` | Low |

### Evidence for the load-bearing ones

**D1.** The constructor takes `{ order, tracks, publish }`. No edges anywhere. `markDirty(A)` adds only `A`; `flush()` publishes exactly `dirty.has(id)`. If `B` observes `A`, `B`'s composed patch changed and `B` is never published. The only correct usage today is `markAllDirty()` every frame, which is exactly what `performance/rig-graph-benchmark.mjs` does, which is why the benchmark never caught it.

**D3.** `flush()` swaps `this.#dirty = new Set()` at the top, then composes and publishes with no `try`. One throwing plugin discards every other pending node permanently.

**D5.** `this.#order = [...order]` with no setter, but `this.#tracks = tracks` is a live reference. A track added to that map after construction exists and never composes. `Motion`/`TrackGroup` `#graphOrder` has the same shape.

**D13.** The graph IR, `#order`, `#tracks`, and `#dirty` are all keyed by `track.id`, and the normalizer rejects duplicate ids in the *static* schema. But `addChild` only checks `this.#children.has(child.id)`, per parent. Two runtime-spawned children under different parents can share an id and collide in the publisher's maps, silently shadowing each other. Precondition for §3.1.

**D2.** `flush()` does `composed.set(id, patch)`; `Track.compose` does `ctx.get(this)` / `ctx.set(this, patch)`. The instance-keyed entries accumulate and work (see R1-E1), the string-keyed ones are pure overhead. The observable failure is `TrackGroup.composeGraph()`, which returns that map with 2n entries, half keyed by `Track` object, so `patches.size` and iteration are both wrong.

**D9.** The IR's dedup key includes `role` and `input`, so `A -> B` as `output` and `A -> B` as `input:"x"` are two legal distinct edges. `#observed.set(track, ...)` holds one entry per source instance, so the second silently overwrites the first. The runtime cannot represent the schema it validates.

## 3. Target design

### 3.1 One canonical ctx key: the track id (fixes D2, requires D13)

Rev 1 proposed a dual-indexed `ComposeContext`. Cheaper and clearer: make **`track.id` the only key**. The IR, `#order`, `#tracks`, `#cache`, and the publish callback are already id-keyed; instance keying is the lone outlier, and the one that cannot survive respawn or be serialized for devtools.

`Track.compose` changes `ctx.get(this)` / `ctx.set(this, ...)` to `ctx.get(this.#id)` / `ctx.set(this.#id, ...)`, keeps the plain `Map`, and keeps the `COMPOSING` sentinel exactly as it is (no `#inFlight` Set, per R1-P3). The publisher and `TrackGroup` drop their redundant `composed.set(id, patch)` line, since `Track` now writes that key itself.

Sound only if ids are globally unique, so **D13 is a prerequisite, not a follow-up**: `GraphPublisher.addTrack` and `TrackGroup.mount` throw on a duplicate id, and `addChild` additionally checks against the mounted host's registry when one is attached.

Net effect in the hot path: one map write per node per flush instead of two, one key space instead of two.

### 3.2 Publisher owns the edges; invalidation is one forward pass (fixes D1, D3, D5, D10)

```js
new GraphPublisher({ graph, tracks, publish, strict = true })
```

State:
- `#order` — topological order, replaceable via `applyGraph(graph)`.
- `#upstream: Map<id, id[]>` — sources per node, straight from `graph.edges`. Upstream, not downstream: it is the direction the data already flows, and it is what a forward pass needs.
- `#marked: Set<id>` — directly invalidated this tick.

`markDirty(id)`: validate the id (throw in strict mode, D10), `#marked.add(id)`. **No traversal.** O(1).

`flush()`: one pass over `#order`, which is topologically sorted, so every node's sources are already resolved when it is reached:

```
dirty = new Set()
for id of #order:
  if #marked.has(id) or any(dirty.has(src) for src of #upstream[id]):
    dirty.add(id)
    compose and publish id
```

One O(V+E) pass per flush, independent of how many `markDirty` calls arrived. That is the fix for R1-P1: 300 marks cost 300 O(1) adds plus one 300-step pass, not 300 BFS traversals. It also makes dirty propagation and the publish set the same computation, so they cannot disagree.

`#marked` is cleared per id **only after** that id's compose and publish both return, inside a `try`/`catch` that collects failures and rethrows as an `AggregateError` at the end (D3). A node that threw stays marked and retries next flush, and because propagation is recomputed from `#marked` each pass, its dependents are automatically still dirty too. No separate bookkeeping.

Topology mutation (D5): `applyGraph(graph, tracks)`, `addTrack(id, track)`, `removeTrack(id)`, `addEdge(edge)`, `removeEdge(edge)`. Each rebuilds `#upstream` and re-runs the topological sort outright (R1-P5). `Motion`/`TrackGroup` gain `applyGraphOrder(order)`.

Invalidation is delivered by a plain injected callback, not the eventBus (R1-P4). `addTrack` sets a private `#onInvalidate` hook on the track; `progress()`, `setObserved()`, `removeObserved()`, `addChild()`, and `removeChild()` call `this.#onInvalidate?.(this.#id)`. Zero allocation per frame. The eventBus stays for genuinely rare lifecycle events like destruction.

### 3.3 Cross-tick caching is opt-in, off by default (D4)

`compose-per-call-scoping-brief.md` deliberately rejected a cross-frame cache ("Option C"), and `Track.test.js` asserts that a second root `compose()` recomputes from scratch, because that is what keeps scrubbing and `seek` correct. Rev 1 proposed exactly the rejected thing. Corrected position:

- **`Track` gets no persistent cache. Per-call scoping stays exactly as specified.** That test keeps passing unchanged.
- The publisher may hold a `#cache` across flushes, but **only under `cache: "persistent"`, defaulting to `"flush"`**, which reproduces today's semantics.
- Be honest about the payoff: for Walker (14 tracks, all animating) a persistent cache buys approximately nothing, because everything is dirty every frame anyway. It pays only in the idle-majority scenario. **D4 is therefore deferred to phase 6 and gated on that benchmark showing a real win.** If it doesn't, we don't ship it.
- If it ships, a dev-only `verifyIncremental` flag full-recomputes after each flush and diffs against `#cache`, throwing on divergence. Test-only, never production, because it is strictly more expensive than not caching.

### 3.4 Observation lifecycle (D7, D6, D9, D8)

**D7, reversing "no reverse registry."** The existing rule (caller must `removeObserved` before destroying) is workable for static rigs authored once. It does not survive dynamic topology: pop a ball mid-chain and the framework offers no way for its observers to find out, so every call site has to remember cleanup, and forgetting produces subtly wrong motion rather than a crash. Adding `#observers: Set<Track>` costs one set insert per wire and makes the dangling case impossible. `destroy()` iterates it, calls `observer.removeObserved(this)`, and emits `track:source-destroyed { id, observerIds }`. `removeChild()` detaches in both directions. This is a deliberate reversal and should be recorded as an amendment to `observe-multisource-brief.md`, not slipped in.

**D6, cycle rejection scoped to graph membership.** Corrected in rev 3. Mutual observation between standalone tracks is a supported, tested feature and the `COMPOSING` back-edge fallback is specified behavior. Neither changes. The DAG constraint is `GraphPublisher`'s: it needs a topological order, and a runtime rewire that closes a loop silently invalidates it.

So cycle validation activates **only for tracks registered in a graph**. `GraphPublisher.addTrack` sets a private guard on the track; while that guard is set, `setObserved` walks upstream from the candidate source via `#observed` and throws `CycleError` **before mutating** if `this` is reachable, so the operation is atomic. Unregistered tracks stay permissive exactly as today. Self-observation throws unconditionally, matching what the normalizer already rejects statically.

User-event rate, so the O(V+E) walk is free, and it fails at the line that caused the bug rather than three frames later in the renderer. Nothing is added to the per-frame path.

**D9.** Re-key `#observed` from Track instance to a composite key matching the IR exactly:

```js
const edgeKey = (sourceId, role, input) => [sourceId, role, input ?? ""].join("");
// value: { source, mapFn, role, input }
```

`observedSources` must keep returning **deduplicated source tracks in insertion order**, because `Track.test.js` asserts `toHaveLength(1)` after re-setting the same source and `toEqual([s2])` after a removal. A new `observedEdges` getter exposes the full edge list. Those existing tests stay green.

**D8.** `compose()` and `getSnapshot()` throw when `#destroyed`, and the publisher drops destroyed tracks via the `track:source-destroyed` hook.

### 3.5 Normalizer hardening (D11, D12)

- Dedup key gets a `` separator, exported as one shared helper used by both the normalizer and `Track`'s `edgeKey`, so the two cannot drift.
- IR gains `valid: errors.length === 0`.
- `topologicalTrackOrder(graph, { strict = true })` throws an aggregated error instead of returning a partial order.
- The normalizer stays pure and diagnostic-only. Throwing is the mount boundary's job.

## 6. Breaking changes

- `GraphPublisher` takes `graph` instead of `order`; `order` accepted for one minor version with a warning and a degraded, edge-less mode.
- `markDirty` throws on unknown ids by default (`strict: false` to opt out).
- Duplicate track ids throw at registration.
- `setObserved` throws on self-observation always, and on cycles once the track is graph-registered.
- `Track.compose` on a destroyed track throws.
- `topologicalTrackOrder` throws on an invalid graph by default.
- `observe-multisource-brief.md`'s "no reverse registry" rule is formally amended.

## 7. Definition of done

- Every defect has a named regression test; no graph test uses a fake track.
- The fuzz suite passes.
- Locked behaviors (per-call compose scoping, the cycle back-edge fallback, standalone mutual observation, `observedSources` semantics) still pass their original tests unmodified.
- D4 either ships with benchmark evidence or is dropped on the record.
- v4.2 phase 5 downgraded with a pointer here; `graphify update .` run.

## 8. Out of scope

- Parallel or worker-based composition.
- A generic reactive/signals runtime.
- Renderer-specific batching.
- Changing the declarative `observes` schema. This makes the runtime match the schema that already exists.
