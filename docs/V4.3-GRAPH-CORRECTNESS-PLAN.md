## Runtime contract

### GraphPublisher

`GraphPublisher({ graph, tracks, publish, strict: true })` owns scheduling and the persistent patch cache. `markDirty(id)` is O(1). `flush()` performs one forward pass over topological order, recomposing only marked nodes and affected dependents while preserving cached patches for idle nodes.

### Failure semantics

Compose failure and publish failure are different faults with different blast radii.

**Compose failure** means the node produced no patch, so its downstream closure is blocked for the rest of the flush, the node stays state-pending, and the next flush republishes the node and its dependents. Compose failures never consume publish retry budget.

**Publish failure** means the patch is valid and only the renderer call failed, so dependents still publish in the same flush and only the failed node retries. Errors are collected and surfaced as `AggregateError` after the pass.

### Publish retry budget

The default remains backward-compatible: `maxAttempts: Infinity` and `backoff: 0`, so a failed node retries every flush forever unless the caller opts in.

```js
const publisher = new GraphPublisher({
  graph,
  tracks,
  publish,
  retry: {
    maxAttempts: 3,
    backoff: 2,
    onExhausted: "retain",
  },
});
```

The policy applies only to publish failures:

- `maxAttempts` counts failed publish calls for one node. A successful publish clears its counter.
- `backoff` is the number of complete flushes skipped between failed attempts. Backoff does not invalidate or recompose the valid cached patch.
- `onExhausted: "retain"` is the default. The node keeps its valid cache and stops retrying, while the original failure still surfaces through `AggregateError`.
- `onExhausted: "drop"` has the same retry stop behavior but explicitly communicates that the renderer may remain stale. It is for callers that prefer bounded work over eventual repaint.
- `resetRetry(id)` clears the node's attempt state and re-arms its publish retry after renderer recovery. Unknown IDs follow the publisher's `strict` behavior.
- Topology changes remove retry state for affected targets and their downstream closure, because their cached patches are invalidated and must be recomposed under the new graph.

A retry budget is not a circuit breaker for state. Compose failures remain pending until composition succeeds, because dropping them would publish missing or stale dependent data.

## Delivered architecture

The audit found four graph representations that could drift: authored `motion.tracks[].observes`, normalized immutable graph IR, mounted Track observation state, and GraphPublisher order/dependency/cache. v4.3 gives each layer one job:

- **Normalizer:** validates authored data and produces immutable IR.
- **Track:** owns live observation edges, reverse observers, local lifecycle, and per-call composition.
- **GraphBinding:** validates and commits graph mutations atomically.
- **GraphPublisher:** owns topological scheduling, invalidation, cache, publishing, and optional retry budgeting.
- **Motion / TrackGroup:** coordinate mounting and timeline placement.
- **React / renderers:** consume published output only.

## Delivered phases

- **Phase 0:** real-Track fixtures, seeded DAG fuzzing, lifecycle and failure contracts.
- **Phase 1:** collision-safe edge identity, lifecycle payloads, ID checks, and strict diagnostics.
- **Phase 2:** Track composite edges, reverse observers, atomic replacement, destroyed guards, invalidation hooks.
- **Phase 3:** GraphBinding candidate validation, stable topo rebuild, atomic mutation and rollback behavior.
- **Phase 4:** graph-aware publisher, O(1) marking, forward flush, dependent publishing, error isolation.
- **Phase 5:** persistent publisher cache, blocked failure handling, idle-majority benchmark.
- **Phase 6:** Motion/TrackGroup and Engine lifecycle integration.

## Acceptance gates

- All unit tests, typecheck, build, package validation, and benchmark pass.
- Incremental output matches a full recomposition oracle under seeded DAG mutation.
- Four graph representations agree after mount, progress, observation mutation, child mutation, unmount, destroy, and failed publish.
- Retry tests prove default compatibility, attempt limits, flush backoff, reset recovery, exhaustion behavior, independent branch progress, and compose-failure isolation.
- No graph test uses fake Tracks.
- Persistent caching remains only if the idle-majority benchmark demonstrates a meaningful reduction in composition work.

## Out of scope

Parallel or worker composition, worker threads, a generic signals runtime, renderer-specific batching, changes to the declarative `observes` schema, and automatic retry-budget selection based on renderer heuristics.
