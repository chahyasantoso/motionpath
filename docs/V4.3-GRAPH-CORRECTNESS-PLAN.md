# MotionPath v4.3: correct graph publishing\n\n> Status: **proposed, revision 5**. This is the v4.3 base plan. It supersedes the \"Complete\" claim on phase 5 of `docs/V4.2-RIG-GRAPH-PLAN.md`.\n>\n> Phase 0 red tests: [`test/v4.3-graph-correctness-phase0`](https://github.com/chahyasantoso/motionpath/tree/test/v4.3-graph-correctness-phase0).\n\n## 0. Executive decision\n\nThe whole-system audit found that the real problem is not one bad `flush()`. There are currently **four graph representations with no authoritative bridge**:\n\n1. authored `motion.tracks[].observes`;\n2. normalized immutable graph IR;\n3. mounted `Track.#observed` object references;\n4. `GraphPublisher`'s separate id/order state.\n\nThey can disagree after runtime mutation. v4.3 therefore makes **Track the authoritative owner of live observation edges**, adds a small **GraphBinding** bridge between Tracks and the publisher, and keeps GraphPublisher authoritative for scheduling, topological order, cache invalidation, and publishing. No component is allowed to mutate one graph representation behind another's back.\n\nThis is the better solution because it gives dynamic rewiring one lifecycle owner while preserving GraphPublisher's graph-wide responsibilities.\n\n---\n\n## 1. Whole-system map\n\n```text\nauthored motion schema\n        |\n        v\nnormalizeObservationGraph()\n        | immutable nodes, edges, diagnostics, stable order\n        v\nMotion / TrackGroup mount\n        | creates real Track instances\n        v\nTrack live graph <----------------------> GraphBinding\n  local state, observed edges,              observes edge/state changes\n  reverse observers, lifecycle              and forwards them transactionally\n        |                                      |\n        | compose(raw, per-call ctx)            v\n        +-------------------------------> GraphPublisher\n                                           graph snapshot/order\n                                           dirty marks + persistent cache\n subscribers / DOM / canvas\n\nGSAP timeline -> Track.progress() -> Track invalidation -> GraphBinding -> publisher.markDirty()\n```\n\n### Audited ownership\n\n| Concern | Owner | Rule |\n|---|---|---|\n| Authored validation | normalizer | pure, no Track instances |\n| Live edge lifecycle | `Track` | all `setObserved`, remove, replace, destroy cleanup go through here |\n| Graph-wide DAG/order | GraphBinding + GraphPublisher | validate candidate snapshot, stable topological sort |\n| Per-call memo/cycle fallback | `Track.compose` | fresh context per external root call, never persistent |\n| Cross-tick cache | GraphPublisher | invalidated only through binding notifications |\n| Timeline/playhead | Track/TrackGroup | GSAP remains the only clock |\n| Renderer output | publisher callback | framework-agnostic |\n| React lifecycle | React hooks | subscribes/presents patches, never edits graph internals |\n\n---\n\n## 2. Findings from the audit\n\n### Critical integration gaps\n\n**A1. GraphPublisher is not wired to real Track invalidation.** It accepts an order and map, but no graph edges, invalidation callback, or lifecycle subscription. `progress()` only notifies raw subscribers; the publisher cannot know which dependents changed.\n\n**A2. `TrackGroup.composeGraph()` and GraphPublisher use string map writes while Track.compose uses Track-instance keys.** The per-call memo itself works, but the public result is polluted and the fake GraphPublisher tests assert a contract real Tracks do not implement.\n\n**A3. Runtime topology has two sources of truth.** `setObserved()` mutates Track-local state; GraphPublisher's order never changes. Any direct rewire can make the publisher compose with stale order, stale dependency metadata, and stale cache.\n\n**A4. Destruction has no graph lifecycle handshake.** `Track.destroy()` kills its timeline and clears outbound observations, but dependents retain the destroyed source. `Motion.unmount`, `TrackGroup.unmount`, and publisher registration are not one transaction.\n\n**A5. Composition and publishing failure semantics are unspecified.** Current flush clears dirty state before work, so a plugin or renderer error loses pending work. A persistent cache also needs a defined blocked-dependent policy.\n\n### Important secondary gaps\n\n**A6. `#observed` is keyed only by source instance.** The normalized IR permits distinct input/output edges and input targets, but runtime last-write-wins collapses them.\n\n**A7. Identity is only locally enforced.** TrackGroup maps are id-keyed, while child ids are checked only under one parent. Dynamic registration can shadow a live track.\n\n**A8. Invalid graph diagnostics are advisory.** The normalizer returns a partial order with errors; `topologicalTrackOrder()` does not enforce validity.\n\n**A9. Existing docs overclaim completion.** v4.2 calls batched publishing complete, while the current code has no real dirty dependency propagation. API docs describe behavior the implementation does not guarantee.\n\n**A10. React/application code can bypass the intended orchestration.** The audit found manual observation wiring and lifecycle cleanup in application briefs. v4.3 must provide one public transaction API before migrating those callers.\n\n---\n\n## 3. Better runtime design\n\n### 3.1 Track owns live edges and reverse observers\n\n`Track` gets: \n\n- `#observedEdges: Map<edgeKey, { source, role, input, mapFn }>`;\n- `#observers: Set<Track>` or an observer-edge map for precise removal;\n- `observedEdges` for full-fidelity inspection;\n- `observedSources` preserved as a deduplicated compatibility view;\n- `replaceObserved(oldSource, newSource, mapFn, opts)` as an atomic operation;\n- lifecycle callbacks for `edge-added`, `edge-removed`, `state-invalidated`, and `destroyed`.\n\nUse a shared delimiter-safe key: `[sourceId, role, input ?? \"\"].join(\"\\")`. Re-setting the same source/role/input replaces one edge; input and output edges coexist.\n\nThe reverse registry is not a second graph. It is the inverse index of Track's one authoritative edge store, maintained transactionally. It makes `destroy()` safe, invalidation cheap, and pop/rewire atomic.\n\nStandalone mutual observation remains compatible: `Track.compose()` keeps the per-call `COMPOSING` fallback. Self-observation is rejected. Graph-managed cycle rejection happens in the binding before a mutation commits.\n\n### 3.2 GraphBinding is the missing bridge\n\nNew internal use case: `GraphBinding`. It binds a set of Tracks to one GraphPublisher and owns the transaction boundary:\n\n```js\nconst binding = new GraphBinding({ graph, tracks, publisher });\nbinding.replaceEdge(oldEdge, newEdge);\nbinding.addTrack(track, { observes });\nbinding.removeTrack(id);\nbinding.destroy();\n```\n\nOn construction, it verifies that live Track edges match the normalized graph. It subscribes to Track lifecycle/invalidation callbacks. On any graph mutation it:\n\n1. clones the current edge snapshot;\n2. applies the candidate mutation;\n3. rejects unknown/duplicate ids, invalid roles, self-edges, or cycles;\n4. rebuilds a stable topological order;\n5. applies the Track edge mutation;\n6. atomically swaps publisher graph metadata and invalidates affected cache nodes;\n7. emits one binding change notification.\n\nIf any step fails, neither Track edges nor publisher state changes. No remove-then-add window. Direct graph-managed `Track.setObserved()` is either routed through the binding or rejected with a clear error; it must never silently bypass the binding.\n\n### 3.3 GraphPublisher does scheduling, not graph mutation\n\n`GraphPublisher` takes a validated graph snapshot and Track map:\n\n```js\nnew GraphPublisher({ graph, tracks, publish, strict = true })\n```\n\nIt stores `order`, upstream ids, marked ids, cache, and known ids. `markDirty()` is O(1). `flush()` makes one topological pass:\n\n```text\nfor id in order:\n  dirty = marked(id) || cache miss || any upstream recomposed\n  if dirty: compose once, cache, publish once\n  if compose/publish fails: keep id pending and block downstream\n```\n\nIndependent branches continue. Failed and blocked nodes retry next flush. Flush throws `AggregateError` after attempting all independent work. The cache belongs here, not Track, so standalone `compose()` still recomputes on each root call.\n\nA dev-only full recomposition oracle compares incremental patches with a fresh per-call composition.\n\n### 3.4 Motion and TrackGroup become lifecycle coordinators\n\n`Motion.init()` constructs the binding after mounting all initial Tracks. `mount`, `unmount`, child spawn, child removal, and `destroy` call binding transactions, not isolated map mutations.\n\n`TrackGroup` owns timeline placement only. Its `composeGraph()` delegates to the binding/publisher and returns exactly one id-keyed patch per live Track. It does not maintain a second graph order independent of the publisher.\n\nDuplicate ids are rejected at binding registration and TrackGroup mount. Destroyed tracks cannot compose or snapshot.\n\n### 3.5 React and renderer boundary\n\nReact hooks continue subscribing to Track snapshots or publisher patches. They do not run their own graph traversal, requestAnimationFrame loop, or manual cleanup sequence. The publisher callback remains renderer-neutral.\n\n---\n\n## 4. Migration and compatibility\n\n### Preserved\n\n- `Track.compose(rawData?)` public signature and per-call semantics.\n- Standalone mutual-observation cycle fallback.\n- `setObserved(source, mapFn)` and `removeObserved(source)` basic behavior.\n- `observedSources` compatibility view.\n- GSAP ticker/master timeline ownership.\n- renderer-neutral publish callback.\n\n### Deliberately changed\n\n- Graph-managed rewires use `GraphBinding`/`replaceObserved`, not free-form direct mutation.\n- Destroying a source automatically detaches its dependent edges.\n- `compose()` and `getSnapshot()` throw after destruction.\n- Unknown ids, duplicate ids, invalid graph mutations, and cycle-creating managed rewires throw before mutation.\n- `GraphPublisher({ graph })` replaces order-only construction; order-only mode is temporary compatibility and has no dependency propagation.\n- `TrackGroup.composeGraph()` returns one id-keyed entry per live Track.\n\n### Compatibility adapter\n\nFor one migration window, direct `setObserved()` may remain available for standalone Tracks. Once a Track is bound, it must carry a binding token and route graph-managed mutations through the binding. This avoids silently allowing two owners.\n\n---\n\n## 5. Implementation phases\n\n**Phase 0, complete:** real-Track red tests and seeded fuzz fixtures. Keep existing Track tests as locked behavior.\n\n**Phase 1, system mapping + contracts:** add GraphBinding interfaces, event payloads, edge key helper, identity rules, and contract tests. No optimization yet.\n\n**Phase 2, Track lifecycle:** composite edge records, reverse observer registry, atomic replace, destroyed guards, invalidation callbacks, standalone compatibility tests.\n\n**Phase 3, binding/topology:** GraphBinding, candidate graph validation, cycle checks, stable topo rebuild, atomic mutation and rollback tests.\n\n**Phase 4, publisher correctness:** graph input, O(1) marks, forward flush, dependent publishing, error isolation, and real-Track integration.\n\n**Phase 5, cache:** persistent publisher cache, invalidation propagation, blocked failures, verify-incremental oracle, idle-majority benchmark.\n\n**Phase 6, Motion/React migration:** TrackGroup/Motion lifecycle integration, remove fake tests, migrate manual application wiring, update API docs.\n\n**Phase 7, hardening:** strict normalizer boundary, delimiter collision fix, duplicate-edge diagnostics, v4.2 status downgrade, `graphify update .`.\n\n---\n\n## 6. Required acceptance tests\n\n1. Authored IR, mounted Track edges, binding snapshot, and publisher order are identical at mount.\n2. Root dirty mark publishes the full downstream closure in topological order.\n3. Sink dirty mark does not publish ancestors.\n4. 300-node sparse graph composes only the invalidated closure.\n5. Diamond shared source composes once per flush; separate root Track calls recompute.\n6. Failed node and blocked dependents retry without losing pending work; independent branches still publish.\n7. Duplicate ids, unknown ids, invalid graph, self-edge, and managed cycle mutations throw with no partial state.\n8. `replaceObserved` is atomic and preserves edge order/metadata.\n9. Destroyed source detaches all reverse observers and removes publisher edges before the next flush.\n10. Input/output same-source edges coexist; compatibility getters remain correct.\n11. Late add/remove/pop/rewire rebuild order and invalidate exactly affected nodes.\n12. TrackGroup, Motion, GraphBinding, and publisher produce one consistent id-keyed patch map.\n13. 500-seed DAG fuzz compares incremental output/order to a from-scratch oracle.\n14. Existing standalone Track tests and React lifecycle tests remain green.\n\n## 7. Definition of done\n\nNo feature is marked complete until the four graph representations agree after mount, progress, observation mutation, child mutation, unmount, destroy, and failed publish. No graph test uses fake Tracks. Persistent caching is accepted only after the sparse benchmark and incremental oracle pass.\n\n## 8. Out of scope\n\nParallel/worker composition, a generic signals runtime, renderer-specific batching, and changing the declarative `observes` schema.\n
