# MotionPath v4.3: Correct Graph Publishing

> **Status:** Proposed, revision 5  
> **Base:** v4.3  
> **Phase 0 tests:** [test/v4.3-graph-correctness-phase0](https://github.com/chahyasantoso/motionpath/tree/test/v4.3-graph-correctness-phase0)

This plan replaces the incorrect “Complete” claim for batched publishing in `docs/V4.2-RIG-GRAPH-PLAN.md`.

## Executive decision

The audit found four graph representations with no authoritative bridge:

1. Authored `motion.tracks[].observes`.
2. The normalized immutable graph IR.
3. Mounted `Track` observation state.
4. `GraphPublisher` order and dirty state.

These can drift after runtime mutation. v4.3 gives each layer one job:

- **Normalizer:** validates authored data and produces immutable IR.
- **Track:** owns live observation edges, reverse observers, local lifecycle, and per-call composition.
- **GraphBinding:** validates and commits graph mutations atomically.
- **GraphPublisher:** owns topological scheduling, invalidation, cache, and publishing.
- **Motion / TrackGroup:** coordinate mounting and timeline placement.
- **React / renderers:** consume published output only.

No layer may mutate a graph representation behind another layer’s back.

## Findings

### Critical

**A1. GraphPublisher is not connected to real Track invalidation.** It receives an order and map, but no dependency graph or state-change callback.

**A2. Dirty propagation is missing.** Marking a source publishes only that source, not its downstream dependents.

**A3. Runtime topology has two sources of truth.** `Track.setObserved()` changes live edges, while publisher order and dependency metadata remain unchanged.

**A4. Destruction has no graph handshake.** A dependent can retain a destroyed source and compose against a killed timeline.

**A5. Flush failure semantics are unsafe.** Dirty state is cleared before composition and publishing finish, so an exception loses pending work.

### Secondary

**A6. Runtime observation is keyed only by source instance.** Distinct input/output edges from the same source overwrite each other.

**A7. IDs are only locally enforced.** ID-keyed graph maps can shadow tracks created under different parents.

**A8. Invalid graph diagnostics are advisory.** The normalizer can return a partial order alongside cycle errors.

**A9. v4.2 documentation overclaims completion.** Batched publishing is not correct against real `Track` instances.

**A10. Application code can bypass orchestration.** Manual observation wiring and cleanup can race with mount, unmount, and destroy.

## Target design

### 1. Track owns live edges

`Track` becomes the authoritative owner of live observation relationships.

It will provide:

- `#observedEdges`: insertion-ordered records keyed by a shared edge key.
- `#observers`: reverse references for automatic cleanup and invalidation.
- `observedEdges`: full-fidelity inspection.
- `observedSources`: deduplicated compatibility view.
- `replaceObserved(oldSource, newSource, mapFn, options)`: atomic rewire.
- Lifecycle notifications for edge changes, invalidation, and destruction.

The shared key is:

```js
[sourceId, role, input ?? ""].join("")
```

This lets input and output edges from one source coexist. Repeating the same source, role, and input replaces the existing edge.

`Track.compose(rawData, ctx)` keeps a fresh per-root context. That context prevents diamond recomputation within one call, but never becomes a cross-frame cache. Standalone mutual observation remains compatible with the existing `COMPOSING` fallback. Self-observation is rejected.

### 2. GraphBinding owns mutation transactions

Add an internal `GraphBinding` use case:

```js
const binding = new GraphBinding({ graph, tracks, publisher });

binding.replaceEdge(oldEdge, newEdge);
binding.addTrack(track, { observes });
binding.removeTrack(id);
binding.destroy();
```

On every mutation, GraphBinding:

1. Clones the current graph snapshot.
2. Applies the candidate change to the clone.
3. Rejects unknown IDs, duplicates, invalid roles, self-edges, and cycles.
4. Rebuilds a stable topological order.
5. Applies the Track edge mutation.
6. Atomically swaps publisher metadata and invalidates affected cache entries.
7. Emits one binding change notification.

If any step fails, neither Track state nor publisher state changes.

Direct mutation of a bound Track must route through GraphBinding or fail clearly. It must never silently bypass the publisher.

### 3. GraphPublisher owns scheduling and cache

Preferred construction:

```js
new GraphPublisher({ graph, tracks, publish, strict: true })
```

Publisher state:

- Current topological order.
- Upstream IDs and reverse dependents.
- Directly marked IDs.
- Last successful patch per ID.
- Registered IDs.

`markDirty(id)` is O(1). `flush()` makes one forward pass over topological order:

```text
for id in order:
  dirty = marked(id) || cache miss || any upstream recomposed
  if dirty:
    compose once
    cache successful patch
    publish once
  if compose or publish fails:
    keep id pending
    block downstream
```

Independent branches continue. Failed and blocked nodes retry on the next flush. Flush reports failures with `AggregateError` after attempting independent work.

The persistent cache belongs to GraphPublisher, not Track. This preserves correct scrubbing and seeking for standalone `Track.compose()` calls.

### 4. Motion and TrackGroup coordinate lifecycle

`Motion.init()` creates the binding after mounting initial tracks. Mount, unmount, child spawn, child removal, and destroy use binding transactions instead of isolated map edits.

`TrackGroup` owns timeline placement only. Its `composeGraph()` delegates to the binding or publisher and returns exactly one patch per live track, keyed by ID.

Duplicate IDs are rejected during binding registration and TrackGroup mounting. Destroyed tracks cannot compose or snapshot.

### 5. React and renderer boundary

React hooks subscribe to Track snapshots or publisher patches. They do not traverse the graph, run a second animation loop, or perform manual graph cleanup. The publisher callback remains renderer-neutral.

## Compatibility

### Preserved

- `Track.compose(rawData?)` public shape and per-call semantics.
- Standalone mutual-observation fallback.
- Basic `setObserved(source, mapFn)` and `removeObserved(source)` behavior.
- `observedSources` compatibility view.
- GSAP as the only clock.
- Renderer-neutral publishing.

### Deliberately changed

- Bound graph rewires use GraphBinding and `replaceObserved`.
- Destroying a source automatically detaches dependent edges.
- `compose()` and `getSnapshot()` throw after destruction.
- Unknown IDs, duplicate IDs, invalid graph mutations, and managed cycles throw before mutation.
- `GraphPublisher({ graph })` replaces order-only construction. Legacy order-only mode is temporary and has no dependency propagation.
- `TrackGroup.composeGraph()` returns one ID-keyed entry per live Track.

For one migration window, direct `setObserved()` remains available for standalone Tracks. A bound Track carries a binding token and routes managed mutations through GraphBinding.

## Implementation phases

### Phase 0: red tests

**Complete on the test branch.** Real Track fixtures, seeded DAG fuzzing, failure cases, topology cases, lifecycle cases, and locked regression tests.

### Phase 1: contracts and identity

Add the shared edge-key helper, GraphBinding interfaces, lifecycle event payloads, global ID rules, and contract tests. No optimization yet.

### Phase 2: Track lifecycle

Implement composite edge records, reverse observers, atomic replacement, destroyed guards, invalidation callbacks, and standalone compatibility.

### Phase 3: binding and topology

Implement GraphBinding, candidate-graph validation, cycle checks, stable topological rebuilds, atomic mutation, and rollback.

### Phase 4: publisher correctness

Switch GraphPublisher to graph input, O(1) marks, one forward flush pass, dependent publishing, error isolation, and real-Track integration.

### Phase 5: persistent cache

Add cache invalidation, blocked failures, the incremental verification oracle, and the idle-majority benchmark.

### Phase 6: Motion and React migration

Integrate TrackGroup and Motion lifecycle, remove fake publisher tests, migrate manual application wiring, and update API docs.

### Phase 7: hardening

Enforce strict normalizer boundaries, fix delimiter collisions, improve duplicate-edge diagnostics, downgrade v4.2 status, and run `graphify update .`.

## Acceptance tests

1. Authored IR, mounted Track edges, binding snapshot, and publisher order match at mount.
2. Marking a root publishes its full downstream closure in topological order.
3. Marking a sink does not publish ancestors.
4. A 300-node sparse graph composes only invalidated closure nodes.
5. A diamond source composes once per flush; separate root Track calls recompute.
6. Failed nodes and blocked dependents retry without losing work; independent branches continue.
7. Duplicate IDs, unknown IDs, invalid graphs, self-edges, and managed cycles throw without partial state.
8. `replaceObserved` is atomic and preserves edge order and metadata.
9. Destroyed sources detach reverse observers and publisher edges before the next flush.
10. Input and output edges from one source coexist; compatibility getters remain correct.
11. Late add, remove, pop, and rewire rebuild order and invalidate only affected nodes.
12. TrackGroup, Motion, GraphBinding, and publisher return one consistent ID-keyed patch map.
13. A 500-seed DAG fuzz suite matches incremental output and order against a full recomposition oracle.
14. Existing standalone Track tests and React lifecycle tests remain green.

## Definition of done

No feature is complete until the four graph representations agree after mount, progress, observation mutation, child mutation, unmount, destroy, and failed publish. No graph test uses fake Tracks. Persistent caching is accepted only after the sparse benchmark and incremental oracle pass.

## Out of scope

Parallel or worker composition, worker threads, a generic signals runtime, renderer-specific batching, and changes to the declarative `observes` schema.
