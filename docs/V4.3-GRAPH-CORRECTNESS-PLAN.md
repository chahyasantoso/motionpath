# MotionPath v4.3: Correct Graph Publishing

> **Status:** Implementation merged into `v4.3`; hardening follow-up in progress  
> **Base:** v4.3  
> **Primary implementation:** [PR #65](https://github.com/chahyasantoso/motionpath/pull/65)

This plan replaces the incorrect “Complete” claim for batched publishing in `docs/V4.2-RIG-GRAPH-PLAN.md`.

## Delivered architecture

The audit found four graph representations that could drift:

1. Authored `motion.tracks[].observes`.
2. Normalized immutable graph IR.
3. Mounted `Track` observation state.
4. `GraphPublisher` order, dependency metadata, and cache.

v4.3 now gives each layer one job:

- **Normalizer:** validates authored data and produces immutable IR.
- **Track:** owns live observation edges, reverse observers, local lifecycle, and per-call composition.
- **GraphBinding:** validates and commits graph mutations atomically.
- **GraphPublisher:** owns topological scheduling, invalidation, cache, and publishing.
- **Motion / TrackGroup:** coordinate mounting and timeline placement.
- **React / renderers:** consume published output only.

## Runtime contract

### Track

`Track.compose(rawData, ctx)` uses a fresh per-root context keyed by track ID. The context prevents diamond recomputation during one call but is discarded after the call, preserving correct scrubbing and seeking. Standalone mutual observation remains supported through the `COMPOSING` fallback.

Live observations are insertion-ordered records keyed by:

```js
[sourceId, role, input ?? ""].join("")
```

The NUL delimiter is required. It prevents collisions such as `A` + `BC` and `AB` + `C`. Input and output edges from the same source coexist. `observedSources` remains the compatibility view; `observedEdges` exposes full fidelity.

Destroying a source removes its reverse observer edges. `replaceObserved` performs an atomic pop-and-rewire. Destroyed tracks throw from `compose()` and `getSnapshot()`.

### GraphBinding

GraphBinding is the only managed mutation boundary. It validates candidate graphs, rejects unknown IDs, duplicate edges, self-edges, and cycles, rebuilds stable topological order, then synchronizes Track and publisher state. Invalid mutations leave the previous graph intact.

Standalone `setObserved()` remains available for unbound Tracks. Bound graph changes should use GraphBinding APIs.

### GraphPublisher

`GraphPublisher({ graph, tracks, publish, strict: true })` owns scheduling and the persistent patch cache. `markDirty(id)` is O(1). `flush()` performs one forward pass over topological order, recomposing only marked nodes and affected dependents while preserving cached patches for idle nodes.

### Failure semantics

Compose failure and publish failure are different faults with different blast radii. Conflating them into one dirty set is what produced the v4.3 retry bug, where a retried node looked like a fresh upstream change and forced valid dependents to republish.

**Compose failure** means the node produced no patch, so every dependent would render against missing or stale data:

- the node and its full downstream closure are blocked for the rest of the flush;
- the node stays state-pending, so the next flush republishes the node *and* its dependents;
- publisher state carries this in `#marked`, which propagates through `changed`.

**Publish failure** means the patch is valid and only the renderer call failed, so dependents composed off correct data and are already current:

- dependents still publish in the same flush;
- only the failed node retries, and the retry recomposes it without marking it changed;
- publisher state carries this in `#publishPending`, which never enters `changed`.

In both cases independent branches continue, and errors surface as `AggregateError` after the pass completes. Coverage lives in `GraphPublisher.contract.test.js` (D3, publish failure) and `GraphPublisher.incremental.test.js` (compose-failure blocking, independent-branch isolation, retry scope).

## Delivered phases

- **Phase 0:** real-Track fixtures, seeded DAG fuzzing, lifecycle and failure contracts.
- **Phase 1:** collision-safe edge identity, lifecycle payloads, ID checks, and strict diagnostics.
- **Phase 2:** Track composite edges, reverse observers, atomic replacement, destroyed guards, invalidation hooks.
- **Phase 3:** GraphBinding candidate validation, stable topo rebuild, atomic mutation and rollback behavior.
- **Phase 4:** graph-aware publisher, O(1) marking, forward flush, dependent publishing, error isolation.
- **Phase 5:** persistent publisher cache, blocked failure handling, idle-majority benchmark.
- **Phase 6:** Motion/TrackGroup and Engine lifecycle integration.

## Acceptance gates

- All unit tests, typecheck, build, package validation, and benchmark pass.
- Incremental output matches a full recomposition oracle under seeded DAG mutation.
- Four graph representations agree after mount, progress, observation mutation, child mutation, unmount, destroy, and failed publish.
- No graph test uses fake Tracks.
- Persistent caching remains only if the idle-majority benchmark demonstrates a meaningful reduction in composition work.

## Out of scope

Parallel or worker composition, worker threads, a generic signals runtime, renderer-specific batching, and changes to the declarative `observes` schema.
